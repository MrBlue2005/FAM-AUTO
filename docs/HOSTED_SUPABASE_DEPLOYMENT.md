- A new random operator token of at least 32 random bytes, generated/stored with a password manager. Do not reuse `.tmp/supabase-edge-live-validation.env` or any Phase 3 agent secret.

## 2. Understand the secret boundary

| Name/value | Classification and owner | Where used | Browser exposure |
| --- | --- | --- | --- |
| `SUPABASE_URL` | Supabase-managed, public URL | Edge client; injected by hosted runtime | Safe as a URL, but no browser integration in this phase |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase-managed **server secret** | Existing Edge code calls PostgREST/RPC; bypasses RLS | **NEVER**; also never give it to Local Agent |
| `RX_OPERATOR_API_TOKEN` | Operator/server secret, manually configured | Edge secret and trusted operator's `X-RX-Operator-Token` header | **NEVER**; never pass it to Local Agent |
| `SUPABASE_ACCESS_TOKEN` / CLI login | Operator management secret, not a function env requirement | CLI login/link/deploy | **NEVER** |
| Database password / `SUPABASE_DB_PASSWORD` | Operator database secret, not a function env requirement | CLI link/migrations or privileged SQL connection | **NEVER**; not needed by Local Agent |
| `RX_AGENT_ENROLLMENT_TOKEN` | Short-lived, single-use enrollment secret | Returned by operator API, passed only for the first agent start | **NEVER**; remove after enrollment |
| Agent `agent_secret` | Local Agent credential, generated by `LocalAgentCredentials` | DPAPI CurrentUser file; HTTPS Bearer header; hash in Postgres | **NEVER**; do not export/decrypt it for this runbook |
| `RX_AGENT_CLOUD_URL` | Local Agent public endpoint configuration | `https://<actual-project-ref>.supabase.co/functions/v1/agent-protocol` | URL is public, no browser caller required |
| `RX_AGENT_TRANSPORT_MODE`, `RX_AGENT_DRY_RUN`, intervals, `RX_AGENT_ONCE` | Local Agent non-secret configuration | Windows process only; values below | Not secrets; no reason to publish them |
| `RX_DATA_PATH`, `RX_LOGS_PATH`, `RX_UPLOADS_PATH`, `RX_PROFILES_PATH` | Local-only paths, not cloud metadata | Isolated Windows fixture directories | **Never transmit local paths** |
| `agent_id`, `profile_id` | Non-secret identity metadata, not authentication | Registry, heartbeat, task assignment | Safe metadata, still subject to API authorization |
| Anon/publishable key, `SUPABASE_ANON_KEY`, `SUPABASE_PUBLISHABLE_KEYS` | Supabase-managed public API identifiers | **Not required** by this Edge/agent workflow | Public keys only; do not grant direct control-plane access |
| `SUPABASE_SECRET_KEYS`, `SUPABASE_DB_URL` | Supabase-managed server secrets | Available to runtime, **not used by current function** | **NEVER** |
| `SUPABASE_JWKS`, `SB_REGION`, `SB_EXECUTION_ID`, `DENO_DEPLOYMENT_ID` | Supabase-managed public keys/diagnostics | Not required by current implementation | Not credentials |

The function reads exactly three env names: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `RX_OPERATOR_API_TOKEN`. Hosted Supabase injects the first two; manually configure only the third. Keep the project's legacy service-role key support enabled for this existing implementation; it does not yet read the newer `SUPABASE_SECRET_KEYS` map. Do not upload reserved `SUPABASE_*` variables, substitute a publishable key, or add any server secret to `VITE_*` / `NEXT_PUBLIC_*` / browser code. See [Supabase runtime secrets](https://supabase.com/docs/guides/functions/secrets).

## 4. Check the new database, then deploy all migrations

In the **new dedicated project's Dashboard**, keep the Data API disabled during initial schema installation (Integrations > Data API, or the project's Data API settings). Do this before the first migration: the historical migrations create SECURITY DEFINER functions before the final privilege hardening. The existing Edge implementation needs Data API enabled later. See [Data API access controls](https://supabase.com/docs/guides/api/securing-your-api).

Run in SQL Editor before deployment:

```sql
select current_setting('server_version') as postgres_version;
select e.extname, n.nspname as extension_schema
from pg_extension e join pg_namespace n on n.oid=e.extnamespace
where e.extname='pgcrypto';
select tablename from pg_tables where schemaname='public';
```

Require an empty application schema. The first historical migration revokes privileges on **all existing public tables/functions** from anon/authenticated, so this runbook is not safe for an unrelated existing application database. Require `pgcrypto` in `extensions`, since the validated SQL explicitly calls `extensions.digest/crypt/gen_salt`. Supabase normally provisions it there. If absent, the project operator can run `create extension if not exists pgcrypto with schema extensions;` then recheck. If installed in another schema, stop and investigate; do not drop/move a shared extension blindly. No local data dump or seed import is required.

Migration order is exact and the four checkpoint migrations remain byte-for-byte unchanged:

| Version | Purpose |
| --- | --- |
| `202609070001` | Tables, pgcrypto use, RLS, claim/lease/state functions |
| `202609070002` | Durable idempotency wrappers |
| `202609070003` | Operator enrollment-token issuance and credential revocation |
| `202609080001` | First valid terminal result wins; must not be omitted |
| `202609080002` | Phase 4 preparation: revoke inherited PUBLIC/anon/authenticated RPC privileges; explicitly grant service-role access |

The new migration changes privileges only on the 19 `rx_cp_*` functions and seven control-plane tables. It leaves state transitions, payloads, task results and existing RLS enabled. PostgreSQL grants function execution to PUBLIC by default; revoking only named roles is insufficient, and the original revocation also preceded later RPC creation. This is a concrete hosted exposure issue found during preparation, separate from the accepted Phase 3 direct-table denial matrix. See [PostgreSQL function security](https://www.postgresql.org/docs/current/sql-createfunction.html).

```powershell
Invoke-Supabase db push --linked --dry-run
# On a NEW project expect exactly the five versions listed above. Review before continuing.
Invoke-Supabase db push --linked
Invoke-Supabase migration list --linked
```

Do not use `supabase db reset`, `npm run supabase:dev`, `--include-seed`, `--include-all`, `migration repair`, or restore a local dump against hosted. If migration history differs, stop rather than rewriting history. The old local `supabase:dev` script explicitly resets its database and is not a deployment command.

Before enabling Data API, run these read-only SQL gates. All 19 RPC rows must show `false, false, true`; all seven tables must show RLS enabled and no public-role table privileges:

```sql
select p.proname,
  has_function_privilege('anon',p.oid,'EXECUTE') as anon_execute,
  has_function_privilege('authenticated',p.oid,'EXECUTE') as authenticated_execute,
  has_function_privilege('service_role',p.oid,'EXECUTE') as service_execute
from pg_proc p join pg_namespace n on n.oid=p.pronamespace
where n.nspname='public' and left(p.proname,6)='rx_cp_'
order by p.proname;
select c.relname,c.relrowsecurity,
  has_table_privilege('anon',c.oid,'SELECT,INSERT,UPDATE,DELETE,TRUNCATE,REFERENCES,TRIGGER') as anon_access,
  has_table_privilege('authenticated',c.oid,'SELECT,INSERT,UPDATE,DELETE,TRUNCATE,REFERENCES,TRIGGER') as authenticated_access
from pg_class c join pg_namespace n on n.oid=c.relnamespace
where n.nspname='public' and c.relname in
 ('agents','profiles','agent_credentials','agent_enrollment_tokens','tasks','task_events','idempotency_requests');
```

After both gates pass, enable Data API with `public` exposed so the service-role Edge RPC path can operate. Future migrations adding RPCs must explicitly revoke PUBLIC/anon/authenticated and grant service_role in the same migration; this preparation does not alter defaults for unrelated functions.

## 6. Issue a one-time operator enrollment token

Use the same trusted PowerShell session; avoid transcripts and verbose HTTP logging. This masks input, does not echo the secret, and assigns the response instead of displaying the enrollment token:

```powershell
$rxSecureOperator = Read-Host 'Hosted RX_OPERATOR_API_TOKEN (masked)' -AsSecureString
$rxOperatorPtr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($rxSecureOperator)
try { $rxOperator = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($rxOperatorPtr) }
finally { [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($rxOperatorPtr) }
$rxOperatorHeaders = @{ 'x-rx-operator-token' = $rxOperator }
$rxEnrollmentResponse = Invoke-WebRequest -UseBasicParsing -Method Post `
    -Uri "$rxBaseUrl/v1/operator/enrollment-tokens" -Headers $rxOperatorHeaders `
    -ContentType 'application/json' -Body '{"ttl_seconds":900,"resolver":"hosted-dry-run-operator"}'
if ($rxEnrollmentResponse.StatusCode -ne 201) { throw 'Expected HTTP 201' }
$rxEnrollment = $rxEnrollmentResponse.Content | ConvertFrom-Json
Write-Host 'Operator endpoint: HTTP 201'
```

Operator administration uses the configured header; no browser operator login or operator-enrollment route exists. This request proves the hosted gateway, Edge code, server key and enrollment RPC work together. If it fails, do not start the agent. Diagnose the error/status and non-secret Edge logs first.

Windows Firewall must be enabled for the active network profile; do not disable it or change its global policy. Run:

```powershell

if (-not (Test-Path -LiteralPath $rxTestProgram) -or
    [IO.Path]::GetFileName($rxTestProgram) -cne 'hosted-reconnect-node.exe') {

If firewall policy forbids this test, perform it on an isolated test VM instead. Do not stop the hosted project, change its secrets, disable Data API, disable TLS verification, or disconnect the main workstation.

Observe the same PID remains alive, `HEARTBEAT_FAILED`, then `AGENT_RECONNECTED` after restoring connectivity. Failed heartbeat prevents claiming that cycle. `AgentConnectionManager` schedules backoff at 10, 20, 40, 80, 160, then 300 seconds plus 0-999 ms jitter; actual attempts are also gated by the configured 15-second service ticks. Allow the current delay to elapse rather than restarting the agent. Verify `last_seen_at` for both agent and profile advances. Insert one new DRY_RUN fixture as in step 8 and require one claim and one completion for that new ID, proving polling resumes without replay of the original terminal task. Stop the foreground test agent with Ctrl+C after it is idle.

If connectivity fails during RUNNING, do not manually repost/requeue or start a second copy of the agent. Restore connectivity, allow the next protocol request (or privileged `select public.rx_cp_reconcile_expired_leases();`) to reconcile, and inspect the original task/events. A RUNNING lease that expires becomes OUTCOME_UNKNOWN; an expired unstarted CLAIMED lease may requeue. The only exception to terminal immutability is explicit operator resolution of OUTCOME_UNKNOWN. Investigate it before invoking the existing `/v1/operator/tasks/<id>/resolve` route; REQUEUE is an explicit operator action, never automatic. Initial hosted execution remains dry even during failure recovery.

## 10. Rollback and recovery

1. Stop only the isolated hosted agent after a dry task finishes. Do not change the operational Local Agent configuration or Chromium data. Retain the fixture identity/DPAPI record for diagnosis; closing this PowerShell session removes its process env settings.
2. For a failed first deployment, keep Data API disabled until all five migrations and permission gates succeed. Inspect `migration list --linked`; correct the failure and apply pending migrations. Do not reset hosted, delete migration history, drop tables, or undo `202609080001/202609080002`.
3. If a published function must be withdrawn, record its revision and run `Invoke-Supabase functions delete agent-protocol --project-ref $rxProjectRef`. Confirm only that named function is targeted. Retain all database state and secrets; redeploy the reviewed function from this preparation checkout when ready. Deleting the function alone does not replace RPC access control, so retain the permission migration.
4. If an Edge code change alone fails later, redeploy the last known-good `agent-protocol` source with the same explicit project ref/config. Prefer forward-only migrations for schema fixes. Do not restore an old database snapshot over newer task outcomes or credentials as routine rollback; use project backup recovery only after an operator reviews data loss and active leases.
5. If a test agent must be retired, stop it, find its credential IDs without selecting hashes, then invoke the privileged revocation RPC in SQL Editor:

```sql
select credential_id,revoked_at from public.agent_credentials where agent_id='<actual test agent_id>';
select public.rx_cp_revoke_credential('<actual credential_id>'::uuid,'hosted-test-retirement');
```

6. Rotate an exposed operator token in Edge secrets. Do not print token/key values in logs or attempt to rotate Supabase-managed keys by copying replacements into browser/agent config. Review affected credentials if any secret was exposed.
